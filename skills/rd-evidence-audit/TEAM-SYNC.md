# Team-sync

Some teams keep several people's weekly evidence in lockstep — same weeks, same evidence, same task structure — because they pair or group up on the same work and each still needs an individual R&D record. This is a legitimate, but high-consequence, branch: you're about to write into other named people's official records, and the roster can be two people or a dozen.

## Before doing anything

Get the requester to confirm, in these terms specifically:

- Who exactly is on the sync roster? Get every name/account explicitly — don't infer membership from a shared board, a similar task title, or "everyone on this board seems to have the same tasks." A roster of five is not five separate pairs; confirm the whole list once, up front.
- Is this an established, understood practice on the team (not something you're inventing now)?
- Should the synced content be an **exact copy** of the requester's evidence (same PRs, same technical description) across the whole roster, or should each teammate's be **independently grounded** in what they actually worked on?
- Confirm each teammate's account individually — don't infer identity from a similar name or a parallel task title.

If the answer is "exact copy," that means the evidence across the roster will cite PRs authored by the requester, not by each teammate — say this back plainly, for the full roster, and get explicit confirmation before proceeding. This is the one place in this skill where copying, rather than independently grounding, evidence is intentional — because the sync convention itself is the justification, not a diff.

## While syncing

- Handle the roster one teammate at a time. Find where each person's board diverges from the requester's first (compare week by week — status, evidence presence, title) rather than re-writing everything from scratch for everyone.
- Strip all first-person or attributing language from the copied text — each teammate's record should read as their own, with no mention of the requester or any other roster member by name.
- Apply steps 5–7 from the main skill (draft and get sign-off, write then verify, check holiday-adjusted time allocation) to **every** teammate's tasks exactly as you would the requester's — more people on the roster is not a reason to rush any one of them.
- Batch the sign-off: present the full plan for the whole roster before writing anything for anyone, so the requester approves one coherent picture rather than a trickle of small confirmations.
- Never expand a sync beyond the specific weeks/tasks confirmed. If syncing reveals additional gaps unique to one teammate (a week where they have no parallel task at all), stop and ask before creating anything new — that's a bigger decision than mirroring existing content, and it may not apply to the rest of the roster.
